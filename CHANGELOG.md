# Changelog

All notable changes to this project are documented in this file. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `@klaracase/sdk` 0.1.0: REST client for the Klaracase API v1 with all twelve operations.
- `@klaracase/ai-sdk` 0.1.0: Vercel AI SDK tools over the core client.
- Runtime detector that never throws: Deno, Bun, Vercel Edge, Cloudflare Workers, Node, browser,
  else `unknown`. The client now builds on hosts without `process`.
- Option `dangerouslyAllowBrowser`. Without it, the constructor throws `ConfigurationError` (code
  `client_validation`) when `window` and `document` exist.
- CI lanes for Bun and for the Vercel Edge runtime (vitest `edge-runtime` environment).
- `ConfigurationError.code`.
- Complete typed response model for all twelve operations, derived from the example bodies. No
  response type has an index signature any more. `getExtra(body, key)` reads an undeclared key.
- `ResponseMeta.headers` (the response `Headers`).
- `CITATION_VERDICTS` and `isKnownVerdict()`.
- Request enums are strict unions (`mode`, `branch`, `document_type`, `cited_statutes`,
  `direction`, `depth`, facet `type`). Response enums stay open.
- Every input type accepts `undefined` for optional keys (`exactOptionalPropertyTypes` safe).
  A second tsconfig compiles the sources, the tests and the README examples with that flag.
- Type tests that assign every example and conformance body to its response type, and a key
  manifest test that fails when a body carries a key the type does not declare.

- `KlaracaseError.is(error)` and `ConfigurationError.is(error)`, based on `Symbol.for` brands, for
  apps that load both the ESM and the CJS build.
- `ServerError` (5xx except 503, extends `ApiError`).
- `headers` on every error that came with an answer.
- Typed problem extras on every error: `candidates`, `successor`, `unit`, `cap`, `resets_at`, plus
  `retryable` and `retryAfterSeconds`.

- Options `defaultHeaders` (client), `headers` (per request), `logLevel` and `logger`, with the
  `KLARACASE_LOG` environment fallback. Retries log at `debug`, deprecations at `warn`. The token,
  the headers and the query string are never logged.
- `client.withOptions(partial)` returns a new client that shares nothing mutable.

- `decisions.searchAll` and `decisions.citationsAll`: async iterators over pages. `maxPages` is
  required, and capped at 10 and 20.
- Helpers `groupByVerdict(run)`, `assertComplete(run)` and `excerpt(text, finding)`, and the new
  `CitationCheckIncompleteError` (code `citation_check_incomplete`, fields `run_status` and `run`).
- `citationCheckDocuments.upload(file, options?)` takes a `Blob`, `File`, `Uint8Array` or
  `ArrayBuffer` and reads name and media type from a `File`. The old object form still works.
- `citationChecks.createFromFile(file, { wait, reference_date })`: upload, wait and check.

- `@klaracase/sdk/schemas`: zod/mini schemas (loose objects) for every request input and response
  body. `zod` ^4.1 is an optional peer dependency. Type tests keep the inferred types equal to the
  SDK types, and a parse test runs over every example and conformance body.
- JSON Schema files for every schema in `packages/sdk/schemas/`, generated by the build and
  committed. A test fails when they drift from the source.
- `@klaracase/sdk/tools`: `tools` (name, description, JSON Schema) and `callTool(client, name, args,
{ maxChars, budget })`. No runtime dependency.
- Request enum lists as values: `BRANCHES`, `SEARCH_MODES`, `DOCUMENT_TYPES`, `CITED_STATUTES`,
  `CITATION_DIRECTIONS`, `DECISION_SECTIONS`, `FACET_FIELDS`, `MAX_CITED_STATUTES`.
- Whole-input types such as `SearchDecisionsInput` and `GetDecisionInput`.

- API release 0.96.0, additive: `Credits.api_budget` (`cents`, `rate_cents_per_credit`,
  `credits_at_rate`, all integers), absent when the organization has no budget and may not load
  one, never `null`. The type `ApiBudget` and its zod and JSON Schema twins. Unknown keys are kept.
- `InsufficientCreditsError.reason` (open: `api_budget_empty`, `api_budget_not_available`, and the
  reserved `plan_credits_exhausted`) and `InsufficientCreditsError.topUpUrl`. The README says the
  URL is for a human admin and an agent must never open it.
- `InsufficientCreditsError.apiBudget`, the optional `api_budget` member of the 402 problem as an
  `ApiBudget`, `undefined` when the problem has none.
- `TokenLimitReachedError` for the 402 code `token_limit_reached`, with `unit`, `cap`, `spent`,
  `resets_at`, `resetsAt` (a `Date`) and `settingsUrl`. It extends `InsufficientCreditsError`, so
  existing handlers still catch it. `cost` and `balance` are `null` on it.
- `callTool` and the retry policy treat `token_limit_reached` like `insufficient_credits`: never
  retried, returned once for the agent to report to its user.
- README section "Credits, API budget and limits". The conformance pack has 106 cases (four new),
  and the drift guards cover the new body.

- `api.md`, the API reference, generated with typedoc from the JSDoc. Every exported class,
  function, interface, type alias and variable must have JSDoc, and `pnpm docs:api` fails when one
  has none. `pnpm docs:check` fails when `api.md` is out of date.
- `pnpm check-package` runs `publint --strict` and `attw` (Are the Types Wrong?) on both packages.
  CI and the release workflow run it.
- `publishConfig` with `access: public` and `provenance: true` on both packages.
- `examples/` with three programs that run offline against a mock of the API: `quickstart.mjs`,
  `citation-check.mjs` and `agent-tools.mjs`. CI runs them after the build.
- README sections for requirements and runtimes, the browser and proxy pattern, pagination, errors,
  logging, schemas and validation, tools for agents, advanced use and semantic versioning (the 0.x
  policy).

### Docs

- Docs: credit period wording. Credits renew per credit period: the UTC calendar month for free organizations, the paid billing period for subscribers. Unused credits do not roll over. The docs said "calendar month" for every organization.

### Changed

- Documentation correction: paging the same query within a credit period costs no extra credits, so
  `maxPages` is a runaway guard, not a price cap. A changed query, filter or mode is a new charge.
  Check `credits` on each response. This applies to `searchAll` and `citationsAll`.

- `@klaracase/ai-sdk` is a thin wrapper over `@klaracase/sdk/tools`. Its input schemas are now
  `zod/mini` schemas from `@klaracase/sdk/schemas`, its peer dependency on zod is `^4.1.8`, and a
  failure from the API comes back as `{ error: { code, detail, retry_after_seconds } }` instead of
  being thrown. The AI SDK `abortSignal` reaches the client. `cited_statutes` takes at most 5 items.
  `getDecision` asks for at most 4000 characters unless `maxChars` says otherwise.
- The token is held in an ES private field, so it does not show up when a client is inspected.
- `sleep` and `now` are marked `@internal` and are not in the published type files.

- Every error class sets `name` with an explicit string, so a minifier cannot rename it.

- `corpus.coverage` `branches[].count` and `courts[].count` are `Count` objects, not numbers.
- `corpus.facets` has the optional key `norm`. `decisions.get` has the optional `returned_range`.
- `SearchMode`, `Branch`, `DocumentType` and `CitedStatute` are strict unions. Use `Open<...>` for a
  response value.
